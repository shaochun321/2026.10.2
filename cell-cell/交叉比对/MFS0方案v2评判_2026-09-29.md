## 三、补强与新问题

### 1. H1 暴露：按项目先例应判 FAIL，终态 A 的前提不再成立（R-5，须裁定）

项目内两份前序 hold 封存都写明了同一条纪律：

| 封存文件 | discipline 字段 |
|:---|:---|
| `research/d2_recursive_v1/data/d21_hold_seal.json` | "hold exposure => FAIL, no re-run" |
| `research/posterior_v0/data/p0_hold_seal.json` | "hold exposure => FAIL, no re-run (zero-recall)" |
| `research/memory_feedback_substrate_v0/data/heldout_seal.json`（MFS0） | 只写了 "no ... tuned from hold outcomes (zero-recall)"，**漏掉了 exposure ⇒ FAIL 这一条** |

MFS0 的 H1（s23_hold_timing）结果在 Step C 已由同一确定性计算得出（−0.22500876，`readout_feasibility.json`）。按先例它属于暴露，**H1 应判 FAIL，hold6 为 5/6**。而我方 `final_qualification.py:127-130` 的终态规则要求 `HOLD6 == PASS`（6/6）才给 A。所以依照我方自己的规则，**当前记录的终态 A 并未满足**。在 §29 的映射里，这种情况属于"门全过但 hold 未全过"，会落入 UNRESOLVED。

可选处理：
- **(a)（建议）**：追加记录 H1 = FAIL(EXPOSED)，hold6 = 5/6，终态改记为 **A_CONDITIONAL + HOLD_EXPOSURE**，与 Posterior-0 的 A_CONDITIONAL 同构。同时登记 MFS0 封存漏写 exposure 条款这一协议偏离。
- **(b)**：增补一个未暴露的 hold 案例替代 H1。这违反 "no re-run" 纪律，不建议。
- **(c)**：认定 MFS0 封存条款本身就没有 exposure ⇒ FAIL，因而维持 A。这形式上成立，但等于利用自己漏写的条款，不建议。

C3 的处理同 v2 §2.2：它是 Step C 必做项的执行偏离（RailLatch 动力学正对照未做，实际执行的是 w 扰动灵敏度探针），应在同一份收口追加中登记。

### 2. 观察态的增益不是二值：α₊ 会随 Δ 发生时刻而变

v2 §5.3 的不等式 V_set·e^{−T_max/τ_o} > V_th + δ_V 只保证**能检测到**。仓库的 MOSFET 在阈上是线性的，所以观察电容经 FET 形成的门控量是

```
y_eff = gm · (V_o(t_c) − θ)₊，   V_o(t_c) ≈ V_set · e^{−(t_c − t_Δ)/τ_o}
```

也就是说，同为 y=1 的两次经验，Δ 发生得越早，结算时的 V_o 越低，写入越弱。α₊ 于是成为一个随 t_Δ 分布而变的随机量。按 v2 §3.3 自己的公式，E[z]\* 会偏离 p，而且偏差由 later 事件的时间分布决定。

对策（二选一，事先登记）：
- 观察态做**饱和或钳位**，使 V_o 在整个保持期内高于某个上限、FET 输出恒为定值。项目先例：`tss/relations/entry_gate.py` 的 Zener 钳位（b↑ 每次 spike 刷新并钳位）；
- 或者事先登记 t_Δ 的分布，解析求出 E[α₊]，并按 §3.3 求 E[z]\*。

### 3. "未观察到"支路需要互补门，参考失配会直接变成 α₋ ≠ α₊

仓库只有增强型、阈上导通的 MOSFET。"y=0 时导通"的支路需要一个互补量，例如 V_ref − V_o。该参考与观察态满幅之间的任何失配，都会让两路的有效 α 不同，偏差就是 §3.3 的 2/3 那类。v2 §3.3 已要求比较两路的有效 α；这里补充一点：**互补门是失配的主要来源之一**，映射检查应在 y=1 与 y=0 两种结算下分别实测 α。

### 4. 阈值可以精确补偿（支持 v2 §4 的"参考偏置可抵消"）

在仓库 MOSFET 模型（阈上 gm·(v−θ)，阈下精确 0）下，把参考再下移一个阈值，使 FET 输入为

```
u₀' = V_R − V_lo + V_th = V_s·z + V_th      →  conduct = gm·V_s·z
u₁' = V_hi − V_R + V_th = V_s(1−z) + V_th   →  conduct = gm·V_s(1−z)
```

这样就**严格线性**，z=0（或 z=1）时对应支路输出精确为 0，既没有死区，也没有负平衡点。代价是参考必须同时跟踪 r_min、r_max 和 V_th 三个器件量；三者的失配上界应作为 ε_map 的组成部分进入映射检查（与 v2 §8 的三类界限一致）。

### 5. 长单轨迹生成：原则上同意 v2，但项目内已有反面证据

v2 §6 说"连续生成可以是一条长轨迹，成本由实际结构决定"，这一原则成立。但本项目已有实测表明，在同一条 G0 轨迹里后期重复刺激**并不平稳**：
- D2-1 NF-1：site23 的潜伏期从 521 漂移到 637 步，t_on=5000 的 600 步脉冲**零发生**（s23_far）；
- Posterior-0 的 probe1_P600 失败（support_window_too_short），被迫改用 900 步脉冲。

所以"长轨迹连续生成"要面对的不只是计算成本，还有**发生过程本身的非平稳**。这进一步支持 v2 选择模板路线来隔离学习器问题。

### 6. Hτ 尾迹误置位的量化（补充 v2 §5.1）

M 从峰值 0.998 按 τ_M = 0.6 s 衰减到 FET 阈值 0.3，需要 τ_M·ln(0.998/0.3) ≈ **0.72 s**（降到 ε_M = 1e-6 需约 8.3 s）。只要观察电容的置位输入经过同一阈值，相邻周期的最小间隔就应不小于：前一 Δ 的 M 峰值时刻 + 0.72 s + 余量，之后才能开启下一个观察窗。这也是 v2 §10 第四步估算"每次经验时长"时必须计入的一项。

### 7. 预算：计入 attempted 后仍合法，但缺 run_id 级账目

v2 §2.3 指出"失败尝试被排除计数"。把 attempted 计入后逐类重算，**全部在上限之内**：eligibility 2/6、modulation 4/6、persistent 3/6、timing 2/4、factorial 2/4、timing_controls 1/3、path_blocks 3/3、state 2/4、heldout 6/6。

确有缺口的是：ledger_add 对同名条目幂等，Step G/H 的臂重跑（各 2 次）没有单独计数；无效 factorial 的 12 次仿真只记了 1 条。应按 v2 的建议补 run_id 清单。按上面的数字，补账后不会超限。
