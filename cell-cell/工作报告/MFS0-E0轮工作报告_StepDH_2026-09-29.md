## 三、发现的真实问题

1. **本轮执行失误（已纠正，如实登记）**：首版在主仓 checkout 而非 worktree 动手，且 factorial
   每臂只驱动 e 或 M 之一（另一个写死 0）⇒ I_write 按构造恒 0，NEAR 还误读 s23_lag；首版
   predicted_I_z 用手设常数得 −0.672。已全部撤回（git 还原 + 删除），该批 12 次仿真按 §25 记
   `attempted_run`（factorial_sets）。正确重做后 predicted_I_z = −6.078e-2（与 Step C 一致）。
2. **严格 TC 在库存中不存在**：唯一不匹配项是上游脉冲长度（NEAR 600 步 / TC 900 步），由 NF-1
   潜伏期漂移逼出（晚时点 600 步脉冲零发生）。typed 接口上两者喂入 M 链的是同一条 639 步斜坡。
   用户 2026-09-29 裁定条件接受为 TYPED_INTERFACE_MATCHED_TIMING_CONTROL + LIMITATION。
3. **SHA 收口的换行符假阳性**：8 个封存目标在 worktree 中原始字节 SHA ≠ 封存值（封存在主仓
   checkout 计算，两处 checkout 的 CRLF 状态不同）。实证：主仓文件与封存逐字节一致；去 CR 后与
   封存提交 blob 完全相同；自封存提交起 git diff 为空。收口改为两层核查（原始字节照报 + 内容层
   判定），8 项全部登记为 EOL_ONLY。
4. **DEG-025 MEMRISTOR_UPDATE_MISSING_DT**（裁定 §9 要求本轮收口登记）：OPEN，调用侧
   `current = I_write·dt` workaround 全臂统一在役。
